Containerisation for HPC Reproducibility

Containers have become essential tools for ensuring reproducibility in
high-performance computing (HPC) environments.  Unlike traditional software
installation methods that depend on system libraries and configurations,
containers bundle the complete runtime environment — libraries, tools,
configuration files — into a single portable image.

In HPC, rootless container runtimes like Podman and Apptainer (formerly
Singularity) are preferred over Docker because they do not require root
privileges.  Podman provides Docker-compatible CLI commands while running
entirely in user-space.  Apptainer integrates with batch schedulers such
as Slurm and supports MPI-based parallel workloads natively.

Benefits of containerised HPC workflows include:
1. Exact reproducibility: the same container image produces identical
   results regardless of host-system architecture changes.
2. Portability: researchers can develop on a laptop and deploy to a
   supercomputer without modifying code.
3. Version control: container images can be tagged and stored in
   registries (e.g., Docker Hub, GHCR, Harbor) with semantic versioning.
4. Dependency isolation: conflicting library versions for different
   applications coexist peacefully.

GPU-accelerated containers require the NVIDIA Container Toolkit (or CDI)
to expose host GPU drivers inside the container.  The container image
typically bundles CUDA libraries, while the host provides the kernel
driver.  This separation allows updating CUDA without recompiling user
code.

Workflow managers (Nextflow, Snakemake, CWL) integrate natively with
containers, allowing each pipeline step to run in its own image while
passing data through shared volumes or object storage.

For UMRS, the entire inference stack — including vLLM, BentoML, and custom
models — is packaged as container images and orchestrated by Rivault on
Slurm compute nodes.
